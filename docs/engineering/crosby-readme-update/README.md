# Update README

## Purpose

Use this skill to make targeted, minimal updates to an existing README when the project structure or setup has changed.

## When to use it

Use it when:

- features were added,
- the tech stack changed,
- setup instructions moved or expanded,
- or the documentation needs to match current project reality.

## Workflow

1. Read the request, README, and relevant repository evidence. Check recent changes when useful.
2. Locate the relevant README sections.
3. Update only the precise sections affected by the change.
4. Keep the original voice and formatting intact.
5. Apply the requested update and report the diff or summary. For review-only requests, propose changes without editing.

## Good practice

- Prefer narrow documentation updates over broad rewrites.
- Preserve the original tone and structure where possible.
- Update only what is necessary to stay accurate.

## Common pitfalls

- Rewriting large sections unnecessarily.
- Changing the tone of the document for a minor update.
- Adding speculative features or assumptions not grounded in the current code.
