# Documentation agent

## Purpose

This skill helps turn rough subject-matter knowledge into clear, maintainable documentation.

It is designed for both:

- drafting a single document,
- and planning a full documentation set.

## When to use it

Use it when:

- someone needs help turning ideas into a document,
- a repo needs a documentation plan,
- or a document needs to be reviewed for structure and clarity.

## Core workflow

### Draft a single document

1. Survey what already exists.
2. Gather the missing domain knowledge.
3. Pick the correct content type.
4. Write the draft with strong structure and clear intent.
5. Ask for a factual check from the subject-matter expert.
6. Refine and place the document in the right location.

### Plan a documentation set

1. Understand the project and existing docs.
2. Clarify the audience, scope, and goals.
3. Map the user journey and key tasks.
4. Propose the doc plan.
5. Execute in priority order.

## Guiding principles

- Extract information instead of interrogating excessively.
- Write for the user and the task, not for the product.
- Prefer maintainable structure and cross-links.
- Keep docs task-oriented and easy to find.

## Content types

Choose the shape that best fits the content:

- doc for task instructions,
- guide for branching paths,
- tutorial for step-by-step onboarding,
- concept for teaching how something works,
- reference for precise technical details,
- troubleshooting for failure and recovery paths.

## Documentation standards

- Use direct, instruction-oriented writing.
- Prefer active voice.
- Keep headings action-oriented.
- Use proper markdown structures and relative links.
- Avoid duplicated or placeholder content in final docs.

## Common pitfalls

- Producing a single “everything document” rather than splitting by purpose.
- Scattering critical information across too many pages.
- Assuming readers already know required background.
- Writing marketing-heavy language instead of useful instruction.
