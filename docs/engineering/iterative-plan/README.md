# Iterative plan

## Purpose

Use this skill to break a large or ambiguous task into a short sequence of manageable, testable steps.

## When to use it

Choose it when:

- a task is too large to start confidently,
- a refactor is risky,
- or a feature needs incremental delivery.

## Workflow

1. Analyze the requirement.
2. Identify the minimum viable logic needed.
3. Break the work into 3 to 5 sequential steps.
4. Define success criteria for each step.
5. Proceed one step at a time instead of solving everything at once.

## Output pattern

Use a roadmap format like this:

1. Step 1: [Name]
   - Action: brief technical task
   - KISS check: why this is the simplest valid approach
   - Success: how to verify it

## Good practice

- Keep the plan specific and achievable.
- Prefer a linear sequence over a broad design doc.
- Define real success checks for each stage.

## Common pitfalls

- Planning around abstractions that do not yet exist.
- Making the plan too large or too vague.
- Combining multiple concerns into a single step.
